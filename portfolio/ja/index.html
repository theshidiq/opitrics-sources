ソフトウェアエンジニア

カマルアブドゥルシディク

自分が現場で困ったことを、ソフトウェアで解決してきました。

2019年から日本でフルタイムで働いています。最初は製造業、2024年からはホテル業界で勤務しながら、オンラインでコンピュータサイエンスを学んできました。シフト自動作成システムも、アレルゲン読み取りシステムも、出発点はホテルの現場で自分が困ったことです。制約プログラミングとAI・LLMの実装が得意分野です。

ひとつの課題を、続けて追いかけてきました

バラバラの個人開発ではありません。3つとも同じ現場の課題からつながっています。仕事で困り、卒業研究で理論として整理し、そのあと製品として作り直しました。

  2. 1現場

    課題に出会った場所

    勤務先のホテルでは、15〜20名分のシフト表を手作業で作るのに毎回4〜8時間かかっていました（実際に計測した値です）。公平に組むのが難しく、条件の違反もよく起きていました。アレルゲン情報も、日本語の商品ラベルを見ながら手で入力していて、時間がかかるうえ書き間違いも起こりやすい状態でした。

  3. 2卒業研究

    理論として整理する

    シフト作成を組合せ最適化の問題として定式化し、OR-Tools の CP-SAT ソルバーで解くようにしました。結果は17項目のテストで検証しています。これが BINUS University の卒業研究になりました。

  4. 3製品化

    実際に使える形にする

    そこで得た知見をもとに、実際のホテル運用を想定して作り直しました。マルチモーダルLLMが日本語の商品ラベルを読み取り、メニューを組むとアレルゲンが自動で決まります。デモではなく、実際にデプロイして動かしています。

Shift Schedule Manager（OR-Tools）

537 コミット · 2026年9月時点

課題
勤務先ホテルの調理部門（スタッフ15〜20名）では、シフト表の作成に毎回4〜8時間かかっていました。手作業のため公平性を保つのが難しく、条件の違反も頻繁に起きていました。
成果
ソルバーによる生成は30秒以内に完了し、17項目のテストで検証しています。従来は手作業で4〜8時間かかっていた作業です。なお4〜8時間は勤務先での手作業の実測値であり、ソルバーのベンチマーク値ではありません。
担当
個人開発（要件定義・設計・実装・検証・デプロイの全工程）

技術的に工夫した点: 数学的な正しさよりも、必ず使えるシフト表を返すこと

12種類以上の制約があるため、実際のシフトでは条件同士がぶつかり、ソルバーが INFEASIBLE（解なし）を返すことがありました。数学的には正しいのですが、現場では困ります。責任者はその日のシフト表が必要だからです。そこで、一部のハード制約を「非常に高いペナルティを持つソフト制約」に変換しました。これで必ず実行可能な解が返るようになり、どこかで妥協が必要だった場合も、ペナルティの重みでその妥協が見える形になります。何も返さないより、1か所だけ印のついたほぼ完璧なシフト表を返すほうが役に立つと考えました。

React のフロントエンド、Go の WebSocket サーバー、Python の最適化サービスという3層構成です。ソルバー本体は約4,200行で、12種類以上の制約を実装しています。ハード制約は「1人1日1シフト」「カレンダー規則」「スタッフ不在日」「編集済みセルの固定」「休暇数の上限」など、ソフト制約は「連続勤務の回避」「バックアップ要員の配置」「優先ルール」「公平性の均等化」などです。UIは日本の勤務表記（△早番／○通常／◇遅番／×休み）と和暦表示に対応しています。

Front Hotel Agent

352 コミット · 2026年9月時点

課題
ホテルの食事提供では、日本語の商品ラベルからアレルゲン情報を人が読み取って入力していました。手間がかかるうえ、アレルギーに関わる情報なので転記ミスは重大な結果につながります。
成果
ラベルを撮影すると、マルチモーダルLLMが原材料とアレルゲンを読み取り、Supabase に保存します。メニューを組むと、含まれる商品からアレルゲンが自動で決まります。Fly.io にデプロイして動かしています。OCRの精度はまだ計測していないため、数値は載せていません。
担当
個人開発（OCRの処理からAPI設計、デプロイまで全工程）

pnpm のモノレポ構成で、フロントエンドは SvelteKit 5（Runes による状態管理）、APIは NestJS 11（Swagger で仕様を公開）です。日本語ラベルの読み取りには DashScope 経由で Qwen VL-OCR を使っています。メニューに紐づく商品からアレルゲンを自動導出し、食事制限バッジ（ベジタリアン／ヴィーガン／ハラール／グルテンフリー）も同じデータから表示しています。ホスピタリティ業界向けのプロダクト開発企業を志望して作りました。自分が中から知っている業務ドメインだからです。

自己紹介

2019年に技能実習生として来日し、製造業で働いていました。2024年に特定技能1号（宿泊分野）へ在留資格を変更し、現在はホテル業界で勤務しています。2022年からはフルタイムで働きながら BINUS University のコンピュータサイエンス学科（オンライン課程）で学び、2026年12月に卒業予定です。

フルタイムで働きながら学ぶには、学んだことが役に立つ必要がありました。そこで、目の前にある課題に学習を向けました。卒業研究は、自分が働いている調理場のシフトを作るシステムです。チームでも同じやり方をしたいと考えています。現場の本当の課題を見つけ、きちんとモデル化し、検証して、動くものを届けることです。

今後はAI・LLMを使ったアプリケーション開発に取り組みたいと考えています。特にエージェント関連のツールや MCP に興味があります。現在は AWS を学習中です。フルスタックの開発も問題ありませんが、AIの分野を目指しています。
